# nmavitobot v44

v43 confirmed that Avito Pro's internal CPA endpoint returns 401 for the normal client_credentials OAuth token.

v44 adds an optional browser-session fallback for the dynamic CPA threshold.

Optional BotHost environment variables:
- AVITO_AGGREGATY_WEB_COOKIE
- AVITO_AVMEX_WEB_COOKIE
- AVITO_TIR_WEB_COOKIE

Store only the Cookie header value from an already authorized Avito browser session. Never commit it to GitHub.

With a cookie configured, startup logs show auth='cookie' and the bot tries to read:
- advanceThreshold
- advanceBalance
- cpaAlert

Without a cookie, behavior stays on the previous bearer diagnostic and will continue to show 401.

This is still diagnostic only; Telegram alerts for paused views are not enabled until cookie auth is confirmed with HTTP 200.
